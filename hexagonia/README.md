# ヘキサゴニア (hexagonia)

六角形のマスでセル（領土）を広げ、強化し、相手のセルを壊し合う陣取りゲームです。手番はなく、全員がいつでも行動できるリアルタイム対戦です。2〜12人でオンライン対戦できます。

- オンライン対戦は [PeerJS](https://peerjs.com/)（WebRTC の P2P）を使います。部屋を作った人（ホスト）のブラウザがゲームを進め、サーバーはいりません
- 各プレイヤーは別々の端末・ブラウザから参加します（PC・スマホ・タブレット対応）
- 部屋の空いた席に CPU を入れられます。「CPUと遊ぶ」なら、ひとりで通信なしでも遊べます
- ビルドは不要です。素の HTML・CSS・JavaScript だけでできています
- ターン制のモードとチュートリアル・ルール説明が入った以前の版は [/hexagonia_old](../hexagonia_old/) に残してあります

## 遊び方

### 公開する（GitHub Pages）

1. GitHub でこのリポジトリを開き、「Settings」→「Pages」を開く
2. 「Build and deployment」の Source を「Deploy from a branch」にする
3. Branch を `main`、フォルダを `/ (root)` にして「Save」
4. 数分待つと `https://（ユーザー名）.github.io/minigame_by_claude/` のような URL が出ます。その後ろに `hexagonia/` を付けた URL がゲームのページです

> 手元で試すときは、このフォルダで `python3 -m http.server` などを動かして `http://localhost:8000/` を開いてください。

### 部屋を作る・参加する

1. ホストが名前を入れて「部屋を作る」を押す
2. ロビーに出る「部屋ID」か「招待URL」をほかの人に送る
3. 参加する人は招待URLを開くか、部屋IDを入れて「参加する」を押す
4. ロビーで陣営色（12色）を選ぶ
5. 人数が足りないときは、ホストが「＋ CPUを追加」で CPU を入れる（「外す」で外せる。強さも選べる）
6. 必要なら、ホストが「盤面の大きさ（直径）」と「ターン数」を選ぶ
7. 2〜12人そろったら、ホストが「ゲーム開始」を押す。3・2・1 のカウントダウン（音つき）のあとに始まります

### ひとりで遊ぶ（CPU対戦）

トップの「CPUと遊ぶ（ひとりで・通信なし）」を押すと、CPU 1人が入ったロビーになります。CPU は11人まで増やせます。通信はしないので、インターネットにつながっていなくても遊べます。

### 注意

- **ホストはゲームが終わるまでページを閉じたり再読み込みしたりしないでください**。ホストのページを閉じると部屋が終わります（閉じようとすると確認が出ます）。スマホでホストをするときは、スリープや別アプリへの切り替えにも気をつけてください
- ホスト以外の人は、接続が切れても同じブラウザで招待URLを開き直して「参加する」を押せば、同じプレイヤーとして戻れます（切断中も時間は進みます）
- 人数が多いとき（とくに10人以上）は、ホストのブラウザが全員分の通信をこなすので、PCでホストをするのがおすすめです
- 1台で試すときは、ホストとは別のブラウザかシークレットウィンドウで参加してください（同じブラウザだと同じプレイヤーとみなされます）
- 接続の仲介に PeerJS の無料公開サーバー（0.peerjs.com）を、ライブラリの読み込みに cdnjs を使います。公開サーバーが混んでいたり、会社・学校のネットワークなどではつながらないことがあります（TURN サーバーは使っていません）

## ルール

### 準備

- 盤面は大きな六角形です。大きさはふつう人数に合わせて決まります（2〜3人：直径9／4人：11／5〜6人：13／7〜8人：15／9〜12人：17）。ロビーでホストが直径 7〜21マスから選ぶこともできます
- **河川** は、本流が盤面の端から反対側の端へ曲がりくねって流れ、盤面が大きいと支流（半径8以上で1本）が本流に合流します。コアとその周りには流れません。どのコアも、河川を渡らずに十分な広さの島（盤面のマス数 ÷ 人数 の 3/5 以上）を持てない配置になったら作り直します（`RULES.islandShare`）
- 残りのマスの地形は、平原 約80%・**鉱山（◆）**・**森林（▽）** 約10%ずつです。**農地（●）と工場（□）は最初はなく、「発展」で作ります**（`RULES.terrainRatio`）
  - 公平さのため、どのコアにも、距離2（足りなければ3）のマスに鉱山と森林が1つずつ必ずあります
  - それとは別に、空きマスの少なくとも10%を効果のあるマスとして散らします。**盤面の中心に近いほど出やすく**、真ん中ほど豊かな土地になります（`RULES.centerShare`・`RULES.centerBias`）
  - 鉱山マス：拡張したときと強化したときに、戦力トークン +1
  - 農地：発展で作るセル。ターンごとに食料 +1（強化でもらえる食料 +1 とは別）
  - 工場：発展で作るセル。ターンごとに戦力トークン +1
  - 森林マス：このセルがあると、ターンごとに資源 +1（強化でもらえる資源 +1 とは別）
- 各プレイヤーのコア（未強化）は、6人までは盤面の一番外側に等間隔に置かれます（全員が角、または全員が辺になるようにそろえる）。7人以上は約3分の1のコアを内側の輪に置きます
- 全員、資源トークン10個・**戦力トークン**2個・行動力0から始めます（食料は0個）
- **ほかの人の戦力トークンの数と、セルの防御の数は見えません**（資源・食料の数は見えます）

### 行動力とターン

- **手番はなく、いつでも行動できます**
- 拡張・強化・発展・攻撃で **行動力** を1使います。行動力は **5秒に1回復** し、上限は5です。防御・防御の解除は行動力を使いません。行動力は下のバーに丸で出ます
- **30秒ごとの「ターン」** で、全員いっせいに資源を受け取り、食料を作って食べます。次のターンまでの時間は下のバーに出ます
- 決まった回数のターンが終わったら、勝敗を決めます。ターン数は人数に合わせて自動で決まり（4人まで18回＝9分・8人まで16回＝8分・12人まで14回＝7分）、ロビーでホストが10〜30回から選ぶこともできます
- 行動の取り消しはできません

| 行動 | 行動力 | コスト | 内容 |
| --- | --- | --- | --- |
| 拡張 | 1 | 資源2（河川マスは5） | 自分のセルに隣接する空きマスに、未強化セルを置く。河川マスへの拡張は「橋をかける」 |
| 発展 | 1 | 資源4 | 自分の平原のセル（コア以外）1つを **農地**（ターンごとに食料 +1）か **工場**（ターンごとに戦力 +1）にする |
| 強化 | 1 | 資源4 | 自分の未強化セル1つを強化済にする。**戦力トークン +1**。ターンごとの資源・食料も増える |
| 攻撃 | 1 | 戦力1 | 自分の強化済のセル（拠点）に隣接する相手のセル1つを攻撃する（下の「攻撃と防御」） |
| 防御 +1 | 0 | 戦力1 | 自分のセル1つの防御を1増やす（最大6） |
| 防御を解除 | 0 | なし | そのセルにつぎ込んだ戦力トークンが全部戻る |

### ターンごとの資源と食料

- 資源：強化済セル1つにつき +1、森林マスのセルは +1（強化とは別）、コアは常に +2（強化済ならさらに +1）
- 食料：作ってから食べます
  - 作る：コア **+6**、強化済のセル（コアも）1つにつき **+1**、農地のセル1つにつき **+1**
  - 食べる：**セル1つにつき1**（コアや橋も1マスとして数える）
- 余った食料は持ち越して貯まります
- 足りないときは、足りない数だけ **自動でセルを捨てます**（一番大きなかたまりから外れたセル、未強化、コアから遠いものから。コアは捨てません）
- 工場：ターンごとに、工場のセル1つにつき戦力トークン **+1**
- 下のバーの資源・戦力・食料のトークンの横に、ターンごとの収支（例：「+5/ターン」）が出ます。食料が足りなくなりそうなら黄色。ホバーで内訳が見られます

### 攻撃と防御

- **攻撃** は、行動力1と戦力トークン1個で、すぐ決まります（攻防や読み合いはありません）
  - **拠点**：攻撃できるのは、自分の強化済のセル（強化済のコアも）に隣接する相手のセルだけです。攻めたい方向のセルを強化します
  - 相手のセルに防御があれば、防御が1減るだけです
  - 防御が0のときに攻撃すると、そのセルを **壊して空きマスに戻します**。攻撃側のセルにはならないので、取るには別に拡張が必要です
  - 橋は壊されると **落ちて河川に戻ります**
- **防御**：自分のセルを選んで「防御 +1」を押すと、戦力トークンを1個つぎ込んで、そのセルの防御が1増えます（最大6）
  - 「防御を解除」すると、つぎ込んだ戦力トークンが全部戻ってきます
  - **防御の数は自分にしか見えません**。ほかの人には、防御があるかどうかもわかりません。防御を固めた・解除したこともログに出ません
  - 盤面では、セルの縁と、内側の小さな六角形（強化したときに出るもの）のあいだが、防御1つにつき辺1本ぶんずつ、セルの明るい色で埋まっていきます（6で一周）。相手のセルと接している辺から埋まり、残りは接している辺に近いものから
  - セルを壊されたり捨てたりすると、防御はなくなります
- 自分のセルが攻撃されると、そのマスが赤く光り、「攻撃された！」「壊された！」の表示と警報の音、お知らせで知らせます

### イベント

- ターン4〜8回ごとに次のどれか1つが起き、1ターンのあいだ続きます。起きたイベントは画面上部とログに出ます

| マイナス | プラス |
| --- | --- |
| 不作：食料生産が0.5倍 | 豊作：食料生産が1.5倍 |
| 枯渇：資源生産が0.5倍 | 発見：資源生産が1.5倍 |
| 洪水：河川の隣のセル1つにつき食料 −1（食べる量が増える） | 豊漁：河川の隣のセル1つにつき食料 +1 |
| 疫病：行動力の上限 −1 | 祭事：行動力の上限 +1 |

- 倍率の端数は切り捨て。「河川の隣のセル」に橋は数えません

### 河川と橋

- 河川マスにはそのままではセルを置けません。自分のセルの隣の河川マスに、資源5で **橋をかける** と、自分のセルになります
- 橋はふつうのセルと同じく、かたまりのつながりに数え、強化や防御もできます

### 脱落と勝敗

- コアは、防御が0のときに攻撃されると壊されます（空きマスに戻ります）
- コアを壊されたプレイヤーは脱落します。残りのセルは空きマスに戻り、だれのものにもなりません。**資源・戦力・食料は、コアを壊した人が受け継ぎます**
- 切断したまま戻らない人をホストが脱落させたときは、セルは空きマスに戻り、トークンもなくなります
- 自分以外の全員が脱落したら、その時点で勝利
- 最後のターンが終わったら、**つながっている一番大きなかたまり**（隣り合う自分のセルのまとまり）が最も大きい人の勝利（同じなら同率優勝）。プレイヤー一覧の「⬡ 9/12」は「一番大きなかたまり 9 ／ セルの総数 12」です

- 効果音が鳴ります（開始のカウントダウン・ターンの始まり・拡張・強化・攻撃・攻撃が防御に当たった・セルを壊した・攻撃された・イベント・脱落・勝敗など）。音声ファイルは使わず、ブラウザで合成しています
- 「設定」で、色覚多様性に配慮した配色（Okabe-Ito 配色）に切り替えたり、陣営ごとにセルの縁の模様（実線・破線・二重線・点線）を変えたり、効果音を消したりできます。9人以上のときは縁の模様を自動で組み合わせて見分けられるようにします

### しくみ（ホスト権威型）

- ホストのブラウザで `Room` を動かします。盤面の生成もホストが行います
- 参加者は行動の要求（`{ type: 'act', action }`）をホストへ送り、ホストが `engine.js` でルール上可能かを確かめてから状態を更新し、全員に最新の状態を配信します
- `Room` は30秒ごとに `rtTick`（ターンの処理）、5秒ごとに `rtRegen`（行動力の回復）を呼びます。CPU は2.5秒ごとに考えて、よい行動があれば1つずつ打ちます
- 配信する状態からは、ほかの人の戦力トークンの数と、ほかの人のセルの防御の数を消しています
- 状態は 16KB を超えることがあるので、PeerJS の `binary` シリアライズ（大きなメッセージを分割して送れる）を使っています
- 参加者は3秒ごとに生存確認を送り、20秒返事がなければ切断扱いになります
- 部屋の ID の頭は `hexagonia-v2-` です（ターン制の頃の版と混ざらないように）
- ファイルを更新したら、`index.html` の `?v=` の数字を上げてください。GitHub Pages ではブラウザが古いファイルを最大10分ほど使い回すので、上げ忘れると新しい `index.html` と古い `client.js` が混ざって動かないことがあります
- テスト用に `window.HEXAGONIA_P2P` を先に定義すると、PeerJS の読み込み元と接続先（自前の PeerServer など）を差し替えられます

### メンテナンス中の入口（一時的）

- いまはトップの前にパスワードの画面があり、パスワードを入れないとトップ（メインメニュー）に進めません。一度通ると、そのタブを閉じるまでは聞きません
- ページの中で確かめているだけなので、本当の鍵ではありません（ソースを読めば外せます）。ソースにはパスワードそのものではなく SHA-256 の値だけを置いています
- 外すときは、`index.html` の `#gate` を消し、`#top` の `hidden` を外し、`client.js` の `initGate()` まわりを `show('top')` に戻してください

### CPU の考え方

- 強さは **よわい・ふつう・つよい** の3段階で、ホストがロビーで CPU ごとに選べます（最初は「ふつう」）
  - よわい：気まぐれに行動を選び、よい行動が少なければ待つ
  - ふつう：下の考え方のとおり。強化を多め・拡張を控えめにする
  - つよい：ふつうより迷いが少ない
- 人間と同じ公開情報（盤面・全員の資源と食料）だけで考えます。相手の戦力トークンの数と防御の数は見ません
- できる行動それぞれに点数を付けて一番高いものを選び、よい行動がなければ待ちます
  - 相手のコアの方向へ広げることを重視する。鉱山・森林、一番大きなかたまりにつながる拡張も重視（終盤は特に）
  - 相手のセルに面したセルや、相手が近づいてきたセル（2マス以内）の防御を、先に固める（コアは厚く3、強化済のセルは2、ほかは1まで）
  - 攻撃は、価値が高いもの（コア＞強化済のセル）から。相手の防御はセルの種類で見積もり（コア3・強化済2・ほか1）、削りきれそうな戦力があるときだけ狙う
  - 前線のセルの強化（拠点）は、新しく攻撃できるようになる相手のセルが多いほど重視し、相手のコアの隣なら大きく重視する
  - 戦力は強化・鉱山・工場で増やす。自分のコアの近くに相手が来たときは、工場を重視する
  - 食べさせきれないなら広げない。食料が足りなくなりそうなら発展（農地）・強化。食料に余裕があれば、前線から遠いセルを工場にする
  - 橋は、向こう側に新しく取れる土地があるときだけかける
