# 焚き火の夜 (campfire)

真冬の夜、遭難した旅人たちがひとつの焚き火を囲んで夜明けを待つ対戦型ボードゲーム。
CPU対戦（あなた1人＋CPU 2〜4人）と、部屋コードで集まるオンライン対戦（最大5人、空き席はCPU）で遊べます。ブラウザで `index.html` を開くだけで遊べます（単一ファイル・ビルド不要・外部ライブラリなし）。

## 遊び方

- 開始画面で人数（3〜5人）、夜の数（1夜／3夜）、CPUの速さ、効果音のON/OFFを選んで「はじめる」
- **3夜制**（標準）：各夜の夜明けの体温がその夜の得点（凍死は0点）。3夜の合計得点で勝敗を決める。CPUの性格は3夜を通して固定で、最後の結果画面で公開。1回あたり約10分
- 1夜だけ遊ぶ場合は仕様書どおり（夜明けに体温が最も高い生存者の勝ち）
- 自分の手番では行動を1つ選ぶ。カードを押すと使える行動ボタンが光り、もう一度押すと実行
- 「くべる」を押して燃料が複数種類ある場合は、くべるカードを選ぶ
- 凍死したあとは「結果まで早送り」で最後まで飛ばせる（オンラインでは人間が全員凍死したときにホストだけ）

## オンライン対戦

1. 開始画面で名前を入れて「部屋を作る」→ 5文字の部屋コードが出る（http(s)で公開していれば招待リンクもコピーできる）
2. 他の人は名前とコードを入れて「コードで入る」（招待リンク `?room=コード` で開くとコードが入った状態になる）
3. 部屋を作った人（ホスト）が人数・夜の数・CPUの速さを決めて「はじめる」。空いた席はCPU

- 最大5人。ゲーム開始後は途中参加できない
- 途中で抜けた人（タブを閉じた・通信が20秒途絶えた）の席は、それ以降CPUが引き継ぐ。再入室はできない
- ホストがページを閉じると部屋は終わる
- 手番に制限時間はない

### しくみ

- WebRTC の P2P 通信。サーバーは用意しなくてよく、`index.html` を GitHub Pages などに置くだけで動く
- 接続の仲介（シグナリング）には [PeerJS](https://peerjs.com/) の無料公開サーバー（0.peerjs.com）を使う。PeerJS 本体は「部屋を作る／入る」を押したときに cdnjs から読み込むので、CPU対戦はオフラインでも遊べる
- ホストのブラウザがルールエンジンを動かし、各参加者には**その人に見えてよい情報だけ**を送る（他人の手札・山札の順番・CPUの性格は送らない）。参加者は行動をホストに送るだけで、ホストが正しい手か確かめてから受け付ける
- 公開サーバーが混んでいるとつながりにくいことがある。また、ネットワークの組み合わせによっては（双方が厳しいNATの内側など）P2Pで直接つながらないことがある（TURNサーバーは使っていない）
- テスト用に `window.CAMPFIRE_NET` を先に定義すると、PeerJS の読み込み元と接続先（自前の PeerServer など）を差し替えられる

## 実装メモ

- カードの絵柄はSVGで描画（落ち葉・小枝・薪・湿った木・雪の結晶・具材4種・スープ、冷え込みは月・温度計・吹雪）。仕様書9.1の「円・三角・四角・線だけ」より具体的な絵にしている
- 効果音は Web Audio API でその場で合成（音声ファイルなし）。ON/OFF はブラウザに保存される。早送り中は鳴らさない

- ルールの数値はすべて `<script>` 冒頭の `CONFIG` にまとめてある
- 乱数はシード指定可能：`index.html?seed=123`（最初の1マッチに適用。CPUの性格と各夜の乱数がこのシードから決まる。シードはコンソールにも出力）
- `window.campfire` からルールエンジン（`createGame` / `doAction` / `cpuChoose` など）を呼べるので、CPU同士の自動対戦シミュレーションができる
- 画面はエンジンの状態そのものではなく、自分の席から見える情報だけを取り出した「ビュー」（`viewOf`）から描く。ひとり用でもオンラインでも同じ描画コードを使う

## 仕様書で決まっていなかった点の扱い

- 最初のスタートプレイヤーはランダム
- 飲んだスープは捨て札に入れず、ゲームから取り除く（山札にスープを混ぜないため）
- 冷え込みによる体温低下・凍死判定は席0から席順に処理する
- CPUの燃料選択で「火力7への近さ」が同じときは、小さい燃料 → 湿った木を優先
