# Snowfield（スノーフィールド）

協力型サバイバルボードゲームを、ブラウザで遊べるターン制ゲームにしたものです。
準備ラウンド10回のあと、最終猛吹雪の3ラウンドを全員で生き延びれば勝ちです。

現在は **マイルストーン M2**（オンライン対戦・CPU対戦）まで実装しています。

## 遊び方（初めての方向け）

### 1. 必要なもの
[Node.js](https://nodejs.org/ja)（バージョン18以上。「LTS」と書かれたものでOK）をインストールしてください。
インストールできたか確認するには、ターミナル（Windowsは「PowerShell」、Macは「ターミナル」）で次を実行します。

```bash
node -v
```

`v22.0.0` のように数字が出れば準備完了です。

### 2. 初回だけ：部品をインストール
このフォルダ（`snowfield`）の中で実行します。

```bash
cd snowfield
npm install
```

### 3. ゲームを起動
```bash
npm run dev
```

表示された `http://localhost:5173/` をブラウザ（PCのChrome / Edge / Firefox）で開くと遊べます。
止めるときはターミナルで `Ctrl + C` を押します。

### 4. テストを実行（ルール計算の確認）
```bash
npm test
```

### 5. 公開用にまとめる（必要になったら）
```bash
npm run build
```
`packages/web/dist/` に出来上がります。

## 遊び方の種類

起動して最初の画面で選びます。どれもブラウザだけで遊べます（アカウント登録は不要）。

| 種類 | 内容 |
|---|---|
| **CPUと遊ぶ** | 1人で。CPUを1〜4人加えて遊びます |
| **みんなで遊ぶ（オンライン）** | 「部屋を作る」と5文字の部屋IDが出ます。友だちは「部屋ID」を入れて「参加する」（または招待リンクを開く）。ホストが「ゲーム開始」を押すと始まります。ロビーでCPUを足すこともできます（人数は合計2〜5人） |
| **同じ画面で遊ぶ** | 1台のPCで、手番のプレイヤーを順番に操作します（M1と同じ） |

### オンライン対戦のしくみ（知っておくと安心なこと）
- [PeerJS](https://peerjs.com/)（WebRTC）で、ホストのブラウザと参加者のブラウザが直接つながります。専用のゲームサーバーは要りません。
- ゲームの状態は**ホストのブラウザが持ちます**。ホストがブラウザを閉じると部屋も終わります。
- 参加者がうっかり閉じても、同じブラウザのタブで同じ部屋IDに入り直すと、元の席に戻れます（ゲーム中でも可）。
- 接続の仲立ち（シグナリング）には、PeerJS が用意している無料の公開サーバーを使います。社内ネットワークなど一部の環境では、直接つながらないことがあります。
- 自前のPeerServerを使う場合は、`packages/web/src/net.ts` の `peerOptions` を参照してください。

### 切断したとき（仮の扱い）
- 切断中の人の手番は、短い待ち時間のあと**自動で終了**します（何もせず手番だけ進みます。体温・満腹度の減少は通常どおり）。
- 切断中の人は「捨てる」投票で**反対**として扱います（本人の同意なく捨てないため）。
- ロビーでホスト以外が抜けると席が空きます。ホストが抜けると部屋は閉じます。

### CPUについて
- CPUはホストのブラウザで動きます。食べる → 寒ければ焚き火で温まる → 火が弱ければ焚べる → 資源を集める・動物を倒す → かまくら・倉庫を建てる → 最後は焚き火か防寒施設で終える、という単純な方針です。
- CPUは「捨てる」投票に自動で投票します（余っているものには賛成、足りないものには反対）。

## 操作

| やること | 操作 |
|---|---|
| 移動 | 自分の駒をドラッグ。離したマスへ移動（コストと可否がドラッグ中に出ます） |
| 行動 | 自分の駒をクリックすると行動メニュー。選んでも閉じないので続けて選べます |
| 建設 | メニューの「建てる」→ 左下のカードを盤面へドラッグ |
| 建物の情報 | カーソルを合わせるとツールチップ、クリックで右側に詳細（ここで「直す」も可） |
| アイテムを捨てる | 右上のアイコンをクリック → 投票（他の人の票は画面で代わりに押せます） |
| 視点 | 背景ドラッグで移動、ホイール／ボタンで拡大縮小 |
| お絵かき | 右下の「お絵かきモード」。いつでも描けます（行動はできません） |
| 手番の交代 | 上部の「手番を終える」。（同じ画面で遊ぶときは、手番の人に自動で切り替わります）手番外は移動とお絵かきのみ |
| ライト／ダーク | 上部バー（既定はダーク） |

## フォルダ構成

```
snowfield/
├─ packages/
│  ├─ core/   ルール計算（UIに依存しない純粋関数）＋テスト。将来サーバーと共有します
│  │   ├─ src/config.ts   ★ 未確定のルールの設定値はここ
│  │   ├─ src/rules.ts    体温低下・火力・回復などの計算
│  │   ├─ src/game.ts     ゲーム進行（手番・ラウンド・天候・終了判定・各行動）
│  │   ├─ src/board.ts    盤面の判定（移動経路・防寒・所持上限など）
│  │   ├─ src/room.ts     部屋（ロビー・権限チェック・CPU・切断）。通信方法には依存しない
│  │   ├─ src/cpu.ts      CPUの思考
│  │   ├─ src/drawing.ts  お絵かき（1×1マス単位のデータ）
│  │   ├─ src/rng.ts      シード付き乱数（差し替え可能）
│  │   └─ test/           テスト
│  └─ web/    画面（React + Vite）。src/net.ts が PeerJS 通信
└─ README.md
```

- 乱数（苗木の落下・肉の個数・成長期間など）は `core/src/rng.ts` のシード付き乱数で、テストでは固定値に差し替えられます。
- `core` の `applyAction(state, action)` は元の状態を書き換えず新しい状態を返します。M2 のサーバー同期でそのまま使えます。

## 実装した仕様・しなかった仕様

**M1**：仕様書「数値ルール（確定）」のすべて、手番・ラウンド・天候・予報・終了判定、UI仕様（ドラッグ移動、行動メニュー、建設カード、ツールチップ、ズーム／パン、ダーク／ライト、お絵かき、アクセシビリティ）。

**M2**
- オンライン対戦（部屋ID・招待リンク、ロビー、ホスト権威型）。誰がどの席を操作してよいかはホストが確認します（他人の席の操作は拒否）。
- 手番・捨てる投票・お絵かきの同期。お絵かきは手番外でも全員が同時に描け、他人の線も消せます（マス単位のデータ・後勝ち）。
- CPU対戦（CPUのみ／人とCPUの混成）、切断・再接続の扱い。

**まだ**：M3（仕上げ・調整）。CPUの強さの調整、ホストが落ちたときの引き継ぎ（現状は部屋が終了）。

## 未確定事項（仮の値で動かしています。確認させてください）

すべて `packages/core/src/config.ts` の値を書き換えるだけで変更できます。

| 項目 | 現在の仮の値 | 設定名 |
|---|---|---|
| プレイヤー人数 | 2〜5人（画面では3人が既定） | `minPlayers` / `maxPlayers` |
| 準備期間の天候の抽選 | 重み付き抽選（晴れ35・雪30・吹雪12・雨15・猛吹雪8）。毎ラウンド開始時に決まり、次ラウンド分を先に決めて予報にする | `weatherWeights` |
| 猛吹雪での建物HP減少量 | 各手番開始時に -1（準備期間のランダム猛吹雪も同じ） | `blizzardBuildingDamage` |
| 勝敗の判定 | 最終猛吹雪3ラウンドを終えたら勝ち。行動不能から復帰した直後の手番でまた0になったら負け | `loseOnRepeatedIncapacitation` |
| 開始時の共有アイテム | 木材3・野菜1・肉1 | `initialItems` |
| 動物・資源の初期配置 | 焚き火の周囲にランダム（木5・石4・野菜4・動物3。各種1つは移動できる範囲に必ず置く） | `initialSpawn` |
| 苗の成長 | 1〜3ラウンドの一様乱数（成長後HPは3〜7） | `growMin` / `growMax` |
| 動物のHP | 3〜5 | `animalHpMin` / `animalHpMax` |
| 切断時の扱い | 手番は自動で終了、投票は反対扱い（上の「切断したとき」参照） | `skipDisconnectedMs`（`RoomOptions`） |
| お絵かきの色・太さ | 青・灰の2色、太さ固定 | `penColors` |
| 焚べられる範囲 | 焚き火の上、または隣接マスまで | `stokeRange` |

仕様書に書かれていなかったため、次のように判断しています（違えば教えてください）。
- 動物のいるマスには建物を建てられない。
- 「直す」は建物の上か、建物に隣接したマスから行う（プロトタイプに合わせた）。
- 行動不能中は、温まる・食べる・手番終了以外は行えない。
- 体温は移動で0になってもその場では行動不能にならず、手番終了時にだけ判定する。
